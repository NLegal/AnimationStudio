    - `__init__(model_id="black-forest-labs/FLUX.1-dev")`: stores model_id, lazy-loads on first generate
    - `load_model()`: calls `FluxPipeline.from_pretrained(model_id, torch_dtype=torch.bfloat16)` and `enable_model_cpu_offload()`
    - `generate(input: GenerationInput) -> GenerationOutput`: creates `torch.Generator("cpu").manual_seed(input.seed)`, calls `pipe()` with height=1024, width=1024, guidance_scale=3.5, num_inference_steps=50, max_sequence_length=512, returns images + metadata
    - Graceful failure: if `FluxPipeline` import fails or model loading fails, raises `ModelLoadError` with descriptive message (never crashes process)

    **`sdxl_backend.py` — SDXLBackend:**
    - `__init__(model_id="stabilityai/stable-diffusion-xl-base-1.0")`
    - `load_model()`: calls `StableDiffusionXLPipeline.from_pretrained(model_id, torch_dtype=torch.float16)`, `enable_model_cpu_offload()`
    - `generate()`: SDXL generation with height=1024, width=1024, guidance_scale=7.5, num_inference_steps=30
    - Same graceful failure pattern as FluxBackend

    **`pony_backend.py` — PonyBackend:**
    - `__init__(model_id="AstraliteHeart/pony-diffusion-v6-xl")` — SDXL-based Pony Diffusion (check actual latest model ID in community; if unavailable use SDXL with pony-style prompting)
    - `generate()`: similar to SDXL but with pony-specific score tag in prompt (per PonyDiffusion convention, prepend "score_9, score_8_up, score_7_up " to positive prompt for quality filtering)
    - Graceful failure same pattern

    **`comfy_backend.py` — ComfyUIBackend:**
    - Designed for R&D use only (not production per D-08)
    - `__init__(server_url="http://localhost:8188")`: stores ComfyUI server address
    - `load_model()`: validates connection to ComfyUI server (HTTP GET /) — no-op if unreachable (R&D tool, not critical path)
    - `generate()`: 
      - Uses `pycomfyapi.PyComfyClient` if available, otherwise falls back to raw `requests.post()` to ComfyUI API
      - Sends prompt with workflow JSON (loaded from a template file), queues job, polls for completion, retrieves images
      - Graceful failure: if ComfyUI is unreachable, returns GenerationOutput with error metadata and empty images list (never crashes pipeline)

    **`cloud_backend.py` — CloudAPIBackend:**
    - Wraps cloud ML APIs (fal.ai, Replicate, BFL API) behind the GenerationBackend ABC
    - `__init__(provider="fal", api_key=None, model="fal-ai/flux/dev")`: configures provider
    - `load_model()`: validates API key is set (reads from env: FAL_API_KEY, REPLICATE_API_KEY, or BFL_API_KEY); warns if missing but does not crash
    - `generate()`: 
      - For fal.ai: uses `requests.post("https://fal.run/fal-ai/flux/dev", json={"prompt": ..., "seed": ...}, headers={"Authorization": f"Key {api_key}"})`
      - For Replicate: uses similar REST API pattern
      - Polls for completion, downloads resulting image
      - Graceful failure: if API unreachable or key missing, returns GenerationOutput with empty images + error metadata
    - Include `class Provider(str, Enum)` with FAL, REPLICATE, BFL options

    **Error handling EVERY backend:**
    - All backends have a `__init__` that does NOT load models (lazy loading on first generate)
    - `generate()` wraps model loading + inference in try/except — on any error, returns GenerationOutput(images=[], seed=input.seed, metadata={"error": str(e), "backend": self.__class__.__name__})
    - Never raise exceptions from generate() — always return a valid GenerationOutput, even on failure (resilience pattern)

    **`src/pipeline/job_queue.py` — JobQueue:**
    ```python
    from dataclasses import dataclass, field
    from datetime import datetime
    from typing import Optional
    import uuid

    @dataclass
    class Job:
        id: str = field(default_factory=lambda: str(uuid.uuid4()))
        character_id: str = ""
        job_type: str = ""  # 'reference', 'expression', 'pose', 'outfit'
        config: dict = field(default_factory=dict)
        status: str = "pending"  # pending → running → completed / failed
        created_at: datetime = field(default_factory=datetime.now)
        completed_at: Optional[datetime] = None

    class JobQueue:
        def __init__(self, repository=None):
            self._repo = repository  # Optional AssetRepository for persistence

        def create_job(self, character_id: str, job_type: str, config: dict) -> Job:
            ...

        def update_status(self, job_id: str, status: str) -> None:
            ...

        def list_jobs(self, character_id: Optional[str] = None, status: Optional[str] = None) -> list[Job]:
            ...

        def get_job(self, job_id: str) -> Optional[Job]:
            ...
    ```
    Implementation:
    - In-memory storage as primary (jobs are ephemeral — they kick off generation and the results persist via AssetRepository)
    - `create_job()` generates UUID, stores with status='pending', returns Job
    - `update_status()` transitions status through pending→running→completed/failed
    - `list_jobs()` filters by optional character_id and/or status
    - Return Job objects, not dicts

    **`src/pipeline/generation_job.py` — GenerationJob orchestrator:**
    This is the core orchestration class that wires the full pipeline for one job:

    ```python
    class GenerationJob:
        def __init__(self, backend: GenerationBackend, prompt_builder: PromptBuilder,
                     identity_scorer: IdentityScorer, asset_repo: AssetRepository,
                     diversity_filter: Optional[DiversityFilter] = None):
            ...

        async def execute(self, job: Job) -> dict:
            """
            Full pipeline for one generation job:
            1. Resolve character and asset type from job.config
            2. For each asset variant in job.config['variants']:
               a. Build prompt via PromptBuilder
               b. Generate N candidates via backend (with iterative seeds)
               c. Score each candidate via IdentityScorer
               d. Run diversity filter on scored candidates
               e. Save each candidate as AssetModel (state='scored')
               f. Mark top-k as 'shortlisted' for human review
            3. Update job status to 'completed'
            4. Return summary stats: {total_generated, total_scored, shortlisted_ids, duration}
            """
            ...
    ```
    Implementation details:
    - Step 2b: Generate `job.config['count']` images (default 50-100 per D-04), each with unique seed
    - Step 2c: Score ALL generated images, not just a subset — scoring is cheap compared to generation
    - Step 2d: DiversityFilter selects top diverse subset (default 5-15) from scored candidates
    - Step 2e: ALL scored assets saved to AssetRepository with state='scored'; rejected ones are not saved or saved with state='rejected'
    - Step 2f: Shortlisted assets get state='shortlisted' for human review
    - Use `job.config.get('variants', [{'name': 'front'}])` for per-variant iteration
    - Track timing information per job for cost analysis
    - Handle partial failures: if one variant fails, continue with others (log warning)
    - Raise `JobError` on critical failures (backend not initialized, character not found)
