# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** The Review UI surface of Phase 1 (D-17) — human review of generated character
> candidates against approved references: side-by-side comparison, Brand Score + 7 sub-scores,
> drift warnings, expandable metadata, batch compare, and the six lifecycle actions.
> Backend-facing contracts (repository pattern, scoring plugins, adapters) are NOT visual
> contracts and live in 01-RESEARCH.md.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph gaps, inline padding, badge inner padding |
| sm | 8px | Compact element spacing, card inner gaps, score-bar rows |
| md | 16px | Default element spacing, panel padding, content gutter |
| lg | 24px | Section padding, navbar vertical rhythm |
| xl | 32px | Layout gaps between major panels |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (footer breathing room) |

Exceptions: a single half-step of **12px is sanctioned** for form-field gaps and button padding
(`0.75rem` — used by `.gen-form`, `.action-bar`, `.btn`). It is a multiple of 4 and matches the
shipped stylesheet; do not introduce any other off-scale value.

## Typography

Exactly 4 sizes, exactly 2 weights:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.4 |
| Body | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 24px | 600 | 1.2 |

Rules (all sourced from existing implementation):
- **Label** (12px/600): uppercase micro-labels (`.gen-field label`, table `th`, `.asset-state`),
  sub-score bar labels/values, badges.
- **Body** (14px/400): all default text, buttons, inputs, toasts. Base `font-size: 14px` on
  `body` with `line-height: 1.5`.
- **Heading** (20px/600): section headings (`h2`) — e.g. "Reference", "Candidates (N)".
- **Display** (24px/600): page titles (`h1`) and the Brand Score value.
- Weight discipline: regular (400) + semibold (600) ONLY. Legacy `font-weight: 700`
  (navbar brand, Brand Score label/value) normalizes to 600 at next touch — no new 700s.
- Prompts, seeds, model IDs, and file paths render in the monospace stack at 14px body size
  (`.prompt-text`, `.metadata-panel code`) with `word-break: break-word`.

## Color

The UI chrome deliberately mirrors the studio's brand palette (Cocomelon-style pastels:
blue/yellow/pink/green/orange — source: 01-CONTEXT.md Specifics). Values below are the shipped
`:root` tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#faf8f5` (`--bg-body`) | Page background, dominant warm-neutral surface |
| Secondary (30%) | `#ffffff` (`--bg-card`) / `#f0ece8` (`--bg-nav`) | Cards, panels, navbar, table headers, metadata wells, score-bar tracks |
| Accent (10%) | `#b8d4f0` base / `#8ab8e8` dark (`--blue`, `--blue-dark`) | See reserved-for list below |
| Destructive | `#f8c8d8` fill / `#e89ab0` border / `#7a4a4a` text (`--pink` family) | Reject action, failed badges, error toasts, critical drift warnings — destructive/error semantics ONLY |

**Accent reserved for (exhaustive list):**
1. Primary CTA buttons (`.btn-primary` — "Generate", "Build Prompt")
2. Active navigation/tab/batch-grid indicators (`.btn-active`, `.tab-active`)
3. Sub-score bar fills (`.score-bar-fill` blue gradient)
4. Inline links (`a`)

Accent is NEVER used for lifecycle status, approval, or destructive semantics — those own the
four semantic hues below (required by D-17's six actions):

| Semantic | Fill / Border / Text | Reserved for |
|----------|---------------------|--------------|
| Positive (green) | `#b8e8b8` / `#80d080` / `#3a6a3a` | ✓ Approve button, success toasts, approved/production/completed badges, low drift |
| Caution (yellow) | `#f8e8a0` / `#f0d878` / `#8a7a30` | Pending/queued/running badges, ⟳ Regenerate Similar button, caution drift |
| In-flight (orange) | `#f8d0a0` / `#f0b878` / `#7a6a3a` | ▲ Approve & Promote button, promote actions |
| Negative (pink) | `#f8c8d8` / `#e89ab0` / `#7a4a4a` | ✗ Reject button, failed badges, error toasts, critical drift |

Score color coding: `≥ threshold-good` → green-dark, mid band → orange-dark, low → pink-dark
(`.score-good/.score-ok/.score-bad`). No dark or neon colors anywhere (brand rule,
01-CONTEXT.md Specifics).

## Copywriting Contract

Tone: terse internal-tool imperative. Sentence case. Glyph prefix + verb on lifecycle buttons.
Existing shipped strings are canonical — new screens reuse these patterns verbatim.

| Element | Copy |
|---------|------|
| Primary CTA | "Generate" (dashboard generation panel; the section heading "Generate Assets" carries the noun — source: shipped `dashboard.html`) |
| Review primary action | "✓ Approve" |
| Review secondary actions | "▲ Approve & Promote" · "⟳ Regenerate Similar" · "✗ Reject" · "Needs Refinement" (reason input + state transition, per D-17) |
| Empty state heading | "No candidates awaiting review." (review queue card) · "No characters yet." (character roster) |
| Empty state body | Queue: "Run a generation job for this asset type, then return here." Roster: "Use the Generate panel or seed the catalog." (source: shipped `dashboard.html`) — rendered in the dashed-border `.empty-state` card, italic muted |
| Error state | Toast, negative variant: "Network error — action not applied" (offline/request failure) or the server-provided message; fallback when neither exists: "Action failed". Problem is stated, recovery is implicit re-click of the same action (source: shipped `studio.js`) |
| Success feedback | Server-provided confirmation message in a positive toast, e.g. "Candidate approved" |
| Destructive confirmation | "✗ Reject": NO modal dialog — inline reason input beside the action labeled "Reason (optional)" (source: shipped `review.html`); rejection applies immediately, writes to the review history/audit trail, and the asset stays in job workspace per D-16. Same lightweight pattern for Regenerate Similar (spends generation budget — success toast confirms dispatch) |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule. State coverage for this phase's five UI element groups;
> empty/error COPY lives in `## Copywriting Contract` above and is referenced, not restated.

Applicable state considerations resolved: 9 covered, 2 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Candidate grid, review queue, roster/job/library tables | ✅ covered | Every collection renders the dashed `.empty-state` card with documented copy — verified shipped in `review.html` L167, `dashboard.html` L76/L172/L337, `entity_detail.html` L90 |
| populated | Candidate cards, dashboard tables | ✅ covered | Happy path: thumbnail + Brand Score value + 7 sub-score bars + action bar per candidate card; tables render N rows with zebra-free bordered rows |
| loading | Generation progress | ✅ covered | Async jobs surface progress via state badges (queued/running/completed/failed) in Recent Jobs — polling badge swap replaces spinners; no blocking spinners anywhere |
| error | All mutation actions (approve/reject/promote/regenerate) | ✅ covered | Failure raises `.toast-error` (negative pink) with documented error copy; state unchanged, action remains clickable for retry |
| empty | Reference comparison panel (media) | ✅ covered | Missing approved reference renders `.placeholder-empty` box with text "No approved reference" — shipped `review.html` L92–93 |
| error | Candidate/reference `<img>` (media) | ✅ covered | Broken image URLs hide the `<img>` via `onerror` handler rather than showing browser broken-image chrome — shipped pattern in all three templates |
| long-text | Prompt result, generation metadata | ✅ covered | Monospace blocks wrap via `word-break: break-word`; metadata `<details><dl>` two-column grid wraps long values; seeds/model IDs never truncate mid-token |
| zero-one-many | Dashboard collections | ✅ covered | Count-bearing headings ("Candidates (N)", "Motion Cycles (N @ M BPM)") stay grammatical at 0/1/N because headings carry counts, not inflected nouns; empty case swaps to `.empty-state` card |
| overflow | Long tables and batch grids | ✅ covered | Tables and grids grow vertically; page scrolls (internal desktop tool, max-width 1200px centered); batch compare offers fixed 2×2/3×3/4×4 densities instead of infinite grids |
| loading | Candidate thumbnail first paint (media) | 🧪 backstop | Thumbnails have no loading placeholder today; statement: "large candidate images must not shift layout while decoding" — verify via held-out check at UAT; acceptable if images arrive <1s on localhost |
| partial | Asset records missing scores | 🧪 backstop | Statement: "an unscored candidate shows em-dash placeholders in the Brand Score row and skips sub-score bars, never 0.00" — held-out verification; prevents fake precision driving wrong approvals |
| overflow | Character names longer than card width | ⚠ unresolved | Long names in table cells and card headers wrap (CSS default) but no ellipsis policy is decided; planner treats as assumption — revisit only if a name exceeds one line in practice |
